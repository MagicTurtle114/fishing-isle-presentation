  • 回漁人港魚貨市場賣魚賺錢

技術架構

  • 地圖零手工建模：整張地圖由 plugin/worldbuilder.lua 程式化生成，約 1,000 個 Part
  • 純資料設定：魚種在 src/shared.lua、版圖在 config/world.lua，改參數不用動邏輯
  • 三腳本架構：SharedConfig / ServerMain / ClientMain
  • 17 個 Remote（含 2 個 RemoteFunction）做客戶端↔伺服器通訊
  • DataStore 存金幣與圖鑑，全部包在 pcall 裡，失敗退回記憶體

硬約束（改名會壞掉）

海面零件必須叫 Ocean、CanQuery=true、CanCollide=false；
海床 Seabed 必須 CanCollide=true；
魚域半徑只存在模型的 Radius 屬性上。

開發方式：全自動化，不手動點任何 Studio 按鈕

三條自動化線

  • 產生：改 src\ 後重跑產生器 → 透過 Studio MCP 的 execute_luau 直接注入到開啟中的 place，再建地圖
  • 靜態檢查：Luau 編譯全部 5 個檔案，抓語法錯誤不必開 Studio
  • 執行期驗證：自動按 Play、跑探針腳本量測幾何與數值、再關掉

為什麼要走 MCP

這個 Studio 版本缺 HttpService:Base64Decode，外掛一載入就死， 所以改成由外部程序直接把腳本寫進 place。整份程式碼都是這樣灌進去的， 使用者不需要貼程式碼、也不用按任何匯入按鈕。

根因分析：症狀 vs 真正的原因

看起來是「某個東西壞掉」，實際上多是 Roblox API 的細節。

症狀真正原因修法
樹倒下了 Roblox 圓柱的軸向是本地 X（躺平的）。 makePalm() 只疊了傾斜角，少了 90° 的 Z 旋轉， 每一段樹幹都躺在沙灘上。整棵樹的「高度」變成樹幹直徑（2～5 studs）。 每段樹幹疊上 CFrame.Angles(0, 0, math.rad(90) + lean)； 樹冠位置同樣加 90°。
棚子上下反了 屋頂木板的參數 t 方向寫反：bx = sx*HALF_W*(1-t) 讓 t=0 落在外緣、t=1 落在中央， 結果中央低、兩邊高。 bx = sx*HALF_W*t（0 = 屋脊最高）， 旋轉改 -sx*pitch 讓外側那端比內側低。
船突然沉下去 伺服器每幀直接覆寫 AssemblyLinearVelocity.Y， 重力（196.2）一直往下拉。互撞、卡在島壁、彈飛後自由落體時， 寫進去的速度會被碰撞持續抵消，只靠彈簧救不回來。 加 4 個參數：限制空中掉落速度、深度超限額外加力、 計時後直接 PivotTo 抬回水面、生產線上移避免掉到 -140。
浮標永不咬鉤 魚線的 line.Color 必須是 ColorSequence、 line.Transparency 必須是 NumberSequence。 給錯型別在這裡 error，整個 castSession 中斷。 兩個屬性都改成對應的 Sequence 型別。
落水的玩家消失 Seabed 原本 CanCollide=false， 玩家穿過海床一路掉到 FallenPartsDestroyHeight（-140） 被引擎刪掉，沒有任何錯誤訊息。 Seabed.CanCollide = true。
遊戲整個死掉 GetDataStore() 在未發布的 place 會直接 throw。 一旦 throw，後面連接 PlayerAdded（發魚竿） 和主迴圈（浮力、咬鉤判定）的程式碼全部不會執行。 整段包進 pcall，失敗退回記憶體存檔。未發布也照樣能玩。

環境限制

  • game:SaveAs() 在 MCP 沙箱不可用 → 存檔靠 Win32 送 Ctrl+S
  • MCP 的 Luau 解析器不接受鏈式呼叫（a:WaitForChild("x"):Connect()），必須拆兩行
  • PowerShell 5.1 終端是 Big5，寫含跳脫引號的 steps JSON 會炸 → 一律用 .mjs 產生器
  • Studio 關閉時 MCP 回報的 name 欄位可能是 null
  • Edit 模式沒有 Server 資料模型，量地圖要用 datamodel_type: "Edit"
  • Humanoid.SeatPart 唯讀、seat:Sit() 無法真的坐下 → 測試用浮空平台
  • 測試平台必須 CanQuery = false，且玩家要轉身背對陸地，否則拋竿會回報「前面有東西擋住」
  • 伺服器 Fire() 到客戶端的 BindableEvent 收不到 → 測試改用「資料夾實例身份」當觸發
  • 無法自行檢視圖片（截圖存了讀不到）→ 外觀只能靠程式化幾何驗證，不能靠看

刻意沒做（核心版本範圍）

  • 音效全部留空：src/shared.lua 的 Sounds 全是空字串。 填上 Roblox 資產的 SoundId 就會有聲音，沒填也不會出錯
  • 沒有升級、寵物、排行榜（只有 leaderstats 的「金幣」「最大魚」）、任務、交易
  • 收線是簡化版：客戶端 20Hz 回報自己的條位置，伺服器算進度與判定。 理論上可作弊，註解有標
  • 船是街機操控：VehicleSeat + 伺服器直接設速度， 浮力是手寫的簡化模型。開起來穩定，但不會側傾或翻船
  • 海面上限 2048 × 2048：Ocean 是單一 Part， Roblox 的邊長上限就是 2048

從「地圖長不出來」到 17 項問題全修完

遇到的問題
兩大類
使用者回報的 17 項：功能缺失、比例不對、外觀錯誤

技術障礙：Studio 缺 8 支 API、注入沙箱限制、 PowerShell 編碼、伺服器事件收不到、無法看圖只能靠幾何驗證
解題方式
先量測再修
每個症狀都先寫探針腳本量出實際數值，
再對照 API 行為找根因，最後修完重測同一個數字。

例：樹高 2.3–5.1 → 判定為「樹幹直徑」→ 補 90° → 24.7–33.0
最後成果
可玩核心版

最關鍵的三個教訓

  • 症狀和原因常常不同層級。「遊戲死掉」不是遊戲邏輯錯，是 GetDataStore() 在未發布 place 直接 throw，連帶拖垮後面所有初始化。
  • 「沒有魚竿」「船不見了」是同一個原因，不是兩個 bug。 分開查會花掉雙倍時間。
  • Roblox 的預設值常常是直覺的對立面。圓柱的軸是 X、浮力必須完全接管垂直方向、 Seabed 不碰撞會吃掉玩家。
